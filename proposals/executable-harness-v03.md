# Пакет v0.3: от спецификации к доказательству (на консилиум, не применено)

Цель: средний слой «политика → проверяемые требования → архитектура → реализация → свидетельства» исполняется полностью. Сегодня слой требований готов (P1–P8, метрики, lattice), слой доказательств — наполовину (исполняется только canon-pin; 8 векторов declared). Пакет закрывает именно это: правило ≠ доказательство должно стать конструкцией, а не оговоркой.

## WP1. Исполняемый harness для declared-векторов (ядро, дорого)
Суть: каждый из 8 declared-векторов (`conformance/invalid/002–009`) получает runnable replay по образцу `negative-red/replay_red.py`: temp-копия → инъекция → assert exit + маркер в выводе.
Точки реализации (канон):
- Новый `schemas/replay_vectors.py` с картой `id → инъекция → ожидаемый маркер` (совет единогласно: отдельный модуль; CLI вызывает как библиотеку, логика не дублируется — аудит ≠ самопроверка в одном теле).
- `schemas/maqs_way_audit.py::run_all` — новый раздел `executed` (`passed/total` на вектор), wired-принцип как `run_all.sh` 2/3.
- Семантика счетчика (одно предложение, обязательно): `passed` = исход replay совпал с предсказанным (ожидаемое падение, которое упало, — passed); сравнение ожидаемого и фактического exit-кода явное, проглатывание запрещено.
- Три состояния replay (не сливать): caught (поймал) / missed (не поймал — баг канона) / error (не запустился — среда, не вердикт; ≠ RED и ≠ PASS).
- Критерий приемки: `all` зелен только если GREEN-база + все replay сошлись.

## WP2. Калибровка порогов первым измерением (средне)
Суть: прогнать R@5 / temporal / abstention на одной воспроизводимой системе, опубликовать измеренное рядом с indicative, ретаргетировать gate/target.
Обязательно (совет): pre-registration ДО прогона — ожидаемые порядки фиксируются заранее, расхождение обосновывается, а не заглаживается (иначе circular reasoning); среда специфицируется до измерения (модель+версия, железо, seed) — иначе невоспроизводимо по построению.
Кандидат: Mem0@0724291 (SHA-пин уже есть, самая распространенная OSS из трех) с declared-параметрами прогона; статус после — «measured, single-point» (норматив — только после ≥2 систем).
Точки: `evals/` + `maqs-way-standard.json::verification_suite.metrics` + SPEC §3.2 (таблица gate/target) — все три правятся одним пакетом, иначе разъедутся.
Критерий: ни одного числа без источника `{model_id, quantization, context_len, runner, date}`; ML-RFC дисклеймер снимается измерением, не удалением.

## WP3. Машиночитаемый scoreboard (дешево)
Суть: `scoreboard.json`: система × принцип (P1–P8) × вердикт × file:line × SHA+дата. Источник — `docs/audits/{mem0,graphiti,letta}-way-audit.md` (SHA уже зафиксированы: 0724291/14.10, aca3693/15.10, cc4654a/14.10).
Локация (совет, большинство): канон, рядом с manifest/coverage — evidence живет в каноне, промо ссылается. Обновление — J5-пакетом: отчет + scoreboard + SHA-валидация одним коммитом (пятый lockstep); append-only по аудитам, старые строки не переписываются (§6: правки вторым коммитом).
Схема сразу с полями `executed/declared` на вектор + счетчик WP1 `passed/total` (миграция потом дороже честных нулей сейчас).
SHA-резолв: локальный (по имеющимся клонам/докам) — сетевой резолв тянет нерешенный узел scratch-runner и выводит WP3 из «дешевых» (хвост Б).
Критерий: «один контракт — разные реализации» проверяется диффом, а не чтением прозы.

## WP4. `closes_in` обязан существовать (дешево)
Суть: четвертый экземпляр lockstep — значение `closes_in` резолвится против списка версий-мишеней (сегодня туда пишется что угодно).
Точки: `schemas/spec-manifest.json` (+ поле `release_targets`) + те же `_resolve_owner`-зоны в `check_b_coverage.py` / `check_c8_coverage.py`.
Критерий: dangling-фикстура четвертого типа (`closes_in: v9.9` → RED).

## WP5. Evaluator как генератор команд (средне, промо-репо)
Суть: каждый чекбокс `evaluator/index.html` дополнительно выдает команду/вектор самопроверки; штамп self-declared сохраняется.
Точки: `evaluator/index.html` (карта `check → how-to-verify`) + `evaluator/e2e.py` (ассерты на наличие карты).
Критерий: путь к executed прилагается, вранья нет.

## Порядок и зависимости
WP1 → WP4 (параллельно с WP1: файлы не пересекаются — spec-manifest против replay, санкция одна) → WP3 → WP2 → WP5 (дешевое фиксируем до дорогой калибровки; стрелка WP1→WP2 ослаблена — параллель возможна, хвост В). WP1 разблокирует снятие главной оговорки проекта.
